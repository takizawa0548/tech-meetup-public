# エフェクトも避難ハッチ
refは、レンダリングに関与しない避難ハッチだったが、Effectも同様である。主に外部システムとの同期など、Reactの外の処理で使用される。stateの変更に合わせてstateを変更する等、React内で完結できるものをEffectで使用する必要はない。

# エフェクトの使用パターン
・データフェッチ
・イベントリスナーの登録解除
・タイマーの設定クリア
・リソースのクリーンアップ

# Effectとイベントハンドラの区分け
Effectは、値がリアクティブで常にキャッチアップが必要な時に使用する。イベントハンドラはユーザーに実施させる時、選択する。
リアクティブな値を依存配列に含めたくない場合は、useEffectから外に出す。
ロジックであればuseEffectEventを使用するとあるが試験的なもののため注意。

# エフェクトが不要・NGパターン
・state変数を更新するためのEffect。レンダー後に実施されるため再度レンダリングされることとなる。
・ユーザーイベントに使用すること。イベントハンドラで対応するのが基本。（バッチ処理としてまとめられる）
・上記の例に続いて、Effectを数珠つなぎにすることもNG。stateの更新用関数が含まれる場合、複数のレンダリングが発生してしまう。イベントハンドラでまとめることができるのであれば、そちらで対応する。

# Effectを使わない対応
下記２点が基本的な対応
・stateによるレンダリング中に計算する
・コンポーネントのkeyを変更することにより、新しいコンポーネントとして対応させstateを破棄させる

下記は滅多にないことと可読性が落ちるがこういう対応も可能
・前回のprops情報を保持し、変化があれば更新用関数を実施する。（レンダーが再実施される）
