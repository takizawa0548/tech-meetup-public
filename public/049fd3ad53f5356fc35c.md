# context
## propsでのstate受け渡し
親から子コンポーネントへの受け渡し程度なら冗長にならないが孫以降にも受け渡しをしないといけない場合、より複雑になる。
そもそもそこまで影響があるのであれば全体で共通に使えるものへする方法も必要で、それがcontextである。

## contextの作成手順
1.コンテクストを作成する。
2.データを必要とするコンポーネントがそのコンテクストを使用 (use) する。
3.データを指定するコンポーネントがそのコンテクストを提供 (provide) する。

### コンテクストを作成する。
これは初期値のため、各ツリーで値を管理したい場合は、providerを使用します。probiderを使用しなかった場合は、下記の値が使用されます。
```react
import { createContext } from 'react';
export const LevelContext = createContext(1);
```

### コンテクストを使用する

useContextと作成したコンテクストを使用したいコンポーネントがあるファイルでインポート
```react
import { useContext } from 'react';
import { LevelContext } from './LevelContext.js';
```

コンポーネント内で読み取ります。
この定義を書いたコンポーネントは、LevelContextが更新された時に再レンダリングの対象になります。
なお、providerを指定している場合は、その範囲内でのレンダリングとなり、最上位のコンテクストに変更がかかっても対象外となります。
```react
const level = useContext(LevelContext);
```

### コンテクストを提供する 
作成したコンテクストにvalueを渡すことでそれ以降のコンポーネント範囲でグローバルに管理ができる。

```react
import { LevelContext } from './LevelContext.js';

export default function Section({ level, children }) {
  return (
    <section className="section">
      <LevelContext.Provider value={level}>
        {children}
      </LevelContext.Provider>
    </section>
  );
}
```

また、ネストして同一なコンテクストが重複しても直近のproviderを見るため管理が複雑になることはない
```react
export default function Page() {
  return (
    <Section level={1}> {/*以降、level=1で管理される*/}
      <Heading>Title</Heading>
      <Section level={2}> {/*以降、level=2で管理される*/}
        <Heading>Heading</Heading>
        <Heading>Heading</Heading>
        <Heading>Heading</Heading>
        <Section level={3}> {/*以降、level=3で管理される*/}
          <Heading>Sub-heading</Heading>
          <Heading>Sub-heading</Heading>
          <Heading>Sub-heading</Heading>
          <Section level={4}> {/*以降、level=4で管理される*/}
            <Heading>Sub-sub-heading</Heading>
            <Heading>Sub-sub-heading</Heading>
            <Heading>Sub-sub-heading</Heading>
          </Section>
        </Section>
      </Section>
    </Section>
  );
}
```

コンテクストのprovider配下までは親階層のコンテクストの設定を参照できるため、下記のような設定も可能
※詳しくは公式ページ参照
```react
export default function Section({ children }) {
  const level = useContext(LevelContext); //親のコンテクストを呼ぶ
  return (
    <section className="section">
      <LevelContext.Provider value={level + 1}>　{/*+1で新しいコンテクストを指定*/}
        {children}
      </LevelContext.Provider>
    </section>
  );
}
```

## コンテクストのさまざまな用途
・テーマ
外観を変化させる必要があるコンポーネントで使用する。
・現在のアカウント
多現在ログインしているユーザを知るためにコンテクストを入れることで、ツリーのどこからでも読み取りが容易になる。
・ルーティング
ほとんどのルーティングソリューションは、現在のルートを保持するために内部でコンテクストを使用しています。
・state管理
リデューサとコンテクストを一緒に使用することで複雑な stateを離れたコンポーネントへ受け渡すことができる。
