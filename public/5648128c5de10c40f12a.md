# stateについて
stateは変数ではなくスナップショットのように振る舞う。
スナップショットになぜ例えるかというと、state自体は別に管理しており、set関数が動いた時に返すからである。
例えば、下記のような記述だとレンダー時には、全て同じ値を指している（スナップショット）ため＋３インクリメントすることはない。
次回のレンダーでnumber+1の準備を３回するだけである。

```react
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button onClick={() => {
        setNumber(number + 1); //初期レンダー時のnumberは全て0である
        setNumber(number + 1);
        setNumber(number + 1);
      }}>+3</button>
    </>
  )
}
```

同時に言えることは、イベントハンドラ内のset関数はバッチ処理されて一回のレンダーにまとめられているということ。（効率的）
また、他の関数も同じバッチ処理としてまとめられている。ただし、関数が発火するところまでしか監視していないので例えば、setTimeout内で3秒後にset関数を動かすとしてもそれは別のレンダーとして処理される。また、渡されるstateもイベントハンドラが発火した時点のキャプチャになる。
下記の例では、オンクリック発火時、イベントハンドラ内のアラートは0だが、イベントハンドラ外の再レンダー後のためアラートは5になる。
```react
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
        {alert(number)} {/*こっちは5*/}
      <button onClick={() => {
        setNumber(number + 5);
        alert(number); //こっちは0
      }}>+5</button>
    </>
  )
}
```

# 終わりに
イベントハンドラ内のset関数による再レンダーはまとめて行われること。また、JSX内のstateはその時点のキャプチャであり、レンダーが走らない限りset関数をいくつも使っても変化しないことがわかりました。
ここら辺は結構混乱しそうですが、プログラミングを学び始めた時にはよくあることなのでなれて行きたい思います。
