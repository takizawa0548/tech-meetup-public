# GitHub Actions を理解する
## GitHub Actionsとは
Githubのリポジトリなどに対するアクション（プルリクエスト）に対して、ビルド、テスト、デプロイが自動化できるプラットフォーム。
テストを実行する仮想OSは、Linux,macOS,Windowsが提供される。

### ワークフローとは
.github/workflowsで定義されるymlファイル
複数のワークフローを定義することができる。

### イベントとは
ワークフローを実行するためのトリガー

### ジョブとは
ワークフロー内で定義される一連のステップ。順次または並列で実行される。

### アクションとは
GitHub Actions 用のカスタムアプリケーションのこと。公開されてたり再利用性があり、@Checkoutのように利用するもの。

### ランナーとは
ワークフローの実行仮想サーバー。一度に一つのジョブを実行できる。

# ワークフローでカスタマイズされたアクションを使用する
## アクションのメリット
- 再利用可能
    - 呼び出すだけでOK
    - 事前作成済であらゆるケースに対応したアクションがある
- 構成可能
- コミュニティ主導
    - 実績のあるコミュニティが作成したアクションを利用できる

# ワークフローについて
## ワークフローの基本
- 一つ以上のトリガー
- ランナーで起動する一つ以上のジョブ
- ユーザーが定義したスクリプトかアクションがあるステップ

### ワークフローのトリガー
- ワークフローのリポジトリ内で発生するイベント
    - Pushやissue、リリースが作成された時など
- Github外部で発生し、repository_dispatchでキャッチするイベント
- スケジュールされた時刻
- 手動実行

### ジョブ
ジョブごとに使用するOSを定義する
```yml
jobs:
  example-job:
    runs-on: ubuntu-latest
    steps:
```
#### 依存性
needsを利用することでjobsが並列ではなく順次に実行されるようにすることが可能。
```yml
jobs:
  setup:
    runs-on: ubuntu-latest
    steps:
      - run: ./setup_server.sh
  build:
    needs: setup
    runs-on: ubuntu-latest
    steps:
      - run: ./build_server.sh
  test:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - run: ./test_server.sh
```

### matrix
下記の場合だと、node14と16の複数バージョンでジョブを起動する
```yml
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [14, 16]
```
