### コンパイラ
前回の例ですが、エラーを出しているファイルがあってもコンパイルは実行されているので注意
TypeScriptでエラーがある時にコンパイラが動作しないようにするには下記のオプションをつける
```ts
tsc --noEmitOnError hello.ts
```
### 明示的な型宣言
誤った引数の型が来ないように定義できる。
```ts
function greet(person: string, date: Date) {
  console.log(`Hello ${person}, today is ${date.toDateString()}!`);
}
```
コンパイルするとこんな感じ
```js
function greet(person, date) {
    console.log("Hello ".concat(person, ", today is ").concat(date.toDateString(), "!"));
}
```

型が推測できる場合は省略可能されます。型を定義しなくてもエラーが出ない時は推論で解決されている。
```ts
const msg = "hello";
```

# Everyday Types
非同期処理はpromiseを返します。
```ts
async function getFavoriteNumber(): Promise<number> {
  return 26;
}
```
※promiseは、promiseオブジェクトを返し、結果が取得出来次第格納します。同期処理後に結果が返ってくることも特徴。
```ts
async function getFavoriteNumber(): Promise<number> {
  return 26;
}
// Promise: {} 
let test = getFavoriteNumber()
// 同期処理後にPromiseが返されるため遅れて実行される。
test.then((number) => {
    console.log('a')
})
```

### Optional Properties
?を使うと存在しない可能性のある変数も記述できます
```ts
function printName(obj: { first: string; last?: string }) {
```
ただし、?がついた変数についてはundefinedの可能性があるため事前の検証が必要になります。
```ts
if (obj.last !== undefined) {
```

### Union Types
Stringでしか扱えないメソッドを使うとエラーが発生する。
```ts
// Property 'toUpperCase' does not exist on type 'string | number'.
function printId(id: number | string) {
  console.log(id.toUpperCase());
}
```
toUpperCaseに限らずメソッドの説明を読んで型を確認すること
```
(method) String.toUpperCase(): string
```


解決策は、typeOfで判定すること。（配列の場合はisArray)
```ts
function printId(id: number | string) {
 if (typeof id === "string") {
    console.log(id.toUpperCase());
  }
}
```

### typeとinterfaceの違い
interfaceは宣言後も新しいフィールドを追加できます。(typeの方が宣言で把握できるからいいかも）
```ts
interface Animal {
  name: string;
}

interface Animal {
  honey: boolean;
}

const bear:Animal = {name:"kuma", honey:true};
bear.name;
bear.honey;
```
