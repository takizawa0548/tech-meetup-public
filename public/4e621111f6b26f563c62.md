# コンポーネントのメモリ（State)
Stateとは、コンポーネント固有のメモリ

### ローカル変数はレンダー間で保持されない、変更に気づけない
下記のような処理を書いてもレンダリングはされない。
```js
let count = 0; // 再レンダリングされると初期化される
function handleClick() {
    count = count + 1;
}
```
```js
<button onClick={handleClick}>
    next
<button/>
```
```js
{/* 値の変更に気づけないから更新されない */}
<div>{count + 1}<div/>
```

（参考ページ参照）下記のようにボタンをクリックしてカウントを上げていっても表示は変わらなかった。また、修正して再レンダーが始まるとカウントは０からに戻った。

### useState
・レンダー間でデータを保持するstate変数（count)
・変数の更新が再レンダーのトリガになる(setCount)

```react
const [count, setCount] = useState(0); // レンダーされてもデータを保持できる
function handleClick() {
    setCount(count + 1);
}
```
```react
<button onClick={handleClick}>
    next
</button>
```
```react
{/*値が変更されたことを検知再レンダリングされる*/}
<div>{count + 1}</div>
```

### フック
useStateと頭文字に「use」が付く関数はフックという。フックはレンダーされる時に利用可能な特別な関数。
コンポーネントの最上位でしか記述することができないため、コンポーネントで何を使うか宣言するような解釈で捉えると良さそう。

# レンダーとコミット
### レンダー
レンダーの意味は画面を再描画することではない。Reactでコンポーネントの状態やプロパティによって実際のDOM要素に変換するプロセス。レンダー結果が同じならReactはDOMを変換しない。

### レンダリングタイミング
主に下記で覚える。
・Stateの変更
・Propsの変更（react.memoでpropsのプリミティブは抑制可能、関数の場合はuseCallback関数で抑制）
・親コンポーネントが再レンダリングされた時
・Contextの値が変更された時
